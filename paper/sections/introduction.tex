\section{Introduction}
\label{sec:intro}

Software often has to make a decision among fixed options: route a support ticket, classify the intent of a message, or check a claim against evidence.
A chat model can do this, but its answer has to be generated and parsed, which adds latency and formatting failures.
Jev \citep{jev} is a decision model of this kind, and models built in its style are called Jev-style decision models.
They return a probability distribution over the options without generating free-form text, so a new task needs only a prompt and a list of options \citep{li2026llmasjev}.
LLM-as-Jev \citep{li2026llmasjev} shows that a decoder language model already works as such a decision model, with no change to its architecture, tokenizer or vocabulary.
The model sees the options numbered and answers with a number, which works for any number of options without training.
Fine-tuning it to put its probability on the correct number, while keeping it close to the original model, helps most for small models and for tasks with many options.
All the models it studies are decoders, which read the text from left to right.

A decision needs almost no generation: the model reads the input once and then scores the short identifiers of the options.
Decoders are designed for the opposite case, long generation.
Multi-query and grouped-query attention \citep{mqa, gqa} shrink the KV cache so that decoding can run with larger batches, and the parameters this removes are put back in the MLP layers.
\citet{prefillonly} show what this costs when nothing is generated: the large intermediate tensors of the MLP layers cause periodic spikes in GPU memory during prefill, which limit the input length.
An encoder has no generation step and keeps no KV cache, so this trade-off does not shape its design.
We take these as reasons to try an encoder; at the scale of our models, \cref{sec:cost} finds no such memory difference.

An encoder also reads the whole input in both directions.
Its limitation was the head: a classifier head is fixed to one label set and must be trained again for each new task.
A masked language model has no such limit.
It already predicts a word at a masked position, so an option can be scored by asking whether the model fills a mask next to it with ``yes'' or ``no''.
Recent encoders such as ModernBERT \citep{modernbert} and UltraBERT \citep{ultrabert} are pretrained with masked language modelling and can read long inputs, which decision tasks over documents need.

Reading in both directions matters for citing evidence as well.
When a decoder serves many questions about one document, the document usually comes first, so that its KV cache can be reused across questions, as with prefix caching in vLLM \citep{vllm} and RadixAttention in SGLang \citep{sglang}.
The cached document states are then not conditioned on the question.
Our encoder reads the question and the document together, so the evidence head works on document states that are conditioned on the question.

We build an encoder decision model on this basis.
It takes the same prompt and option list as LLM-as-Jev, puts one mask in front of each option, and scores all options in a single forward pass.
It needs no new head and supports a different number of options in every row.
Our contributions are:
\begin{itemize}\setlength{\itemsep}{2pt}\setlength{\topsep}{2pt}
  \item \textbf{An encoder decision model.}
    We fine-tune UltraBERT-380M \citep{ultrabert} with one mask per option and the ``yes'' versus ``no'' prediction at each mask as the option's score.
    It is trained on the same data as LLM-as-Jev \citep{li2026llmasjev}.
  \item \textbf{Training recipes for the encoder.}
    We compare four ways to train on the mask predictions, which differ in how an option is scored and how the scores are turned into probabilities over the options; one of them follows the expert gate of DeepSeek-V3 \citep{deepseekv3}.
    For each we measure accuracy, sensitivity to the order and removal of options, predicted label frequencies and calibration.
  \item \textbf{A comparison with decoders under matched data.}
    We fully fine-tune Qwen3-0.6B \citep{qwen3} on the same examples for the same single epoch, choose learning rates on a dev split, repeat the runs over seeds and evaluate on a test split excluded from model selection.
    We report accuracy, accuracy on external benchmarks, and time per decision, with two LoRA models \citep{lora} reproduced from LLM-as-Jev as references.
  \item \textbf{Predicting supporting evidence.}
    A decision model generates no text, so we train an auxiliary head on the same encoder to predict the annotated evidence for the chosen option; it is not evaluated as an explanation of how the model decides.
    Its labels come from human-marked evidence and from generated labels selected with a reward adapted from SelfCite \citep{selfcite}.
    We compare it with ContextCite \citep{contextcite} and AT2 \citep{at2} on agreement with human evidence on the test set, and on cost.
\end{itemize}
